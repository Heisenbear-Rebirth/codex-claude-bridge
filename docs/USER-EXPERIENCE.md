# 日常连接与维护反馈

## 连贯的交互动画（2026-10-02）

- 项目、会话和提示词分类切换采用 180ms 淡入及轻微位移；正在进行的动画会从当前画面继续，快速点击不会叠加。后台监控刷新保持文字、选区和滚动位置稳定。
- 工作区标签下划线与项目模式选中背景连续移动。目录和原生详情区域在 200ms 内展开收起，关闭的目录内容立即退出键盘交互。
- 弹窗及遮罩以 250ms 同步进出，手机导航使用 260ms 抽屉过渡；提示消息沿相同方向出现和消失，重复提示更新内容而不重播入场。
- 按钮按下即时反馈，悬停位移只用于精细指针。键盘切换及 Esc 立即响应；“减少动态效果”使用短淡入，并取消位移、抽屉、开关和折叠的空间动画。
- 使用浏览器原生 CSS 过渡及 Web Animations API，没有新增依赖。原生详情动画能力不支持时即时展开，功能保持可用。

验证：290 项自动测试通过；10 组动画专项、8 组交互连续性和 8 组重启确认浏览器检查通过，页面错误均为 0。动画专项检查了中间帧、快速反向切换、后台刷新、键盘操作、原生折叠、提示消息、390px 导航、减少动态效果及文本选择。记录见 `.cooperation/verification/motion-browser.json`、`apple-design-polish-browser.json`、`restart-confirmation-browser.json` 和 `motion-full-tests.txt`。

本次仅更新前端资源；当前管理服务读取最新文件，刷新页面即可使用。

本次界面调整参考 Apple 的 [设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles) 与 [状态反馈指南](https://developer.apple.com/design/human-interface-guidelines/feedback)，将重点放在用户当前的目标、可理解的状态和明确的下一步。

## 日常使用

- 连接页根据当前状态显示下一步：允许项目连接、打开已有会话、检查连接，或者直接完成。首次安装用的构建命令、配置片段和内部参数保留在安装文档中，不进入日常连接页。
- 已连接时不再重复显示设置步骤；需要重开面板时，明确提醒先等待当前任务结束。
- “自动管理”按会话保存设置。两个阈值分别说明“空闲时整理”和“优先整理”的实际效果。
- 维护进度显示“保存进度 → 整理上下文 → 恢复任务”，并区分正在处理、等待用户确认、等待连接和需要检查。
- 正常流程自动推进。出现暂停时优先显示一个恢复动作；重发和结束维护等选项放在“更多操作”内，结束维护需确认对待处理消息的处理方式。
- 会话编号、原始原因和错误码放在详情中。无法复现的问题可用“复制诊断信息”提供当前阶段、发生时间和最近一次确认失败原因；诊断不包含回执凭证、完整提示词或对话正文。

## 操作连续性与首屏状态（2026-10-02）

- 会话首屏优先显示当前状态、原因、额度检测时间和需要用户处理的动作。上下文占用与自动管理设置位于其后；整理阈值默认显示摘要，展开后仍可直接编辑并自动保存。
- 关闭提示词设置面板或按 Esc 会保留当前页面中的草稿与光标位置。“恢复默认”和“放弃草稿”都可撤销。草稿未保存时，离开或刷新页面会触发浏览器的离开提示；草稿不写入额外的浏览器持久存储。
- 保存过程中关闭面板仍会处理实际保存结果；保存失败保留草稿。服务器的版本校验仍生效，不覆盖其他窗口的新设置。
- 后台刷新按稳定编号更新现有节点。状态变化、新消息到来和发现其他会话时，保留当前焦点、文字选择、正在编辑的阈值和展开的诊断信息；操作按钮保持与当前记录对应。
- 移动端扩大主要触控区域至至少 44px。导航打开后焦点留在面板内，关闭时回到菜单按钮；选中会话后进入内容标题。导航可以在开合途中反向操作。
- 按钮按下时即时反馈；侧栏和弹窗采用短过渡，并支持减少动态效果、减少透明度和增强对比度。调整窗口大小不播放导航开合动画。

本轮以项目内的隔离服务和 Chrome 验证桌面及 390px 视口，覆盖草稿、撤销、保存失败、保存中关闭、焦点保持、消息文字选择、移动导航和维护动作。证据见 `.cooperation/verification/apple-design-polish-browser.json`；移动布局验证未使用实体手机。正式发布仅替换前端资源，管理服务与原生客户端无需重启。

## 交付确认被拒绝的修复

本地管理记录出现了两种与用户描述吻合的情况，已通过回归测试复现：

1. Claude 的 `<synthetic>` 系统消息覆盖了模型名称；下一次真实回复会被误认为用户切换模型，提前暂停维护。现在忽略占位消息，区分会话中选择的模型与单次响应的模型信息，同时保留对真实模型设置变更的检查。
2. 保存进度阶段达到固定的 10 分钟期限，即使原维护轮次仍在工作，也会被暂停。现在只要能确认是同一原生实例、同一维护轮次，仍在工作或等待权限时就保持确认入口有效。

超时或短暂投递异常造成的暂停，可以接收经原生状态核对的迟到确认。身份、阶段、凭证、工作目录、文档内容、原生轮次与设置仍会验证；新输入、取消或明确的恢复阻断不会因此被绕过。确认通过后仍要等原维护轮次结束，才开始整理上下文。

文件验证期间只发生投递结果或进度观察更新时，不再仅因数据库版本号变化拒绝确认。显式重发会轮换阶段凭证，防止旧请求误确认新一轮。文档副本按内容哈希保存，未被接收的旧副本不会阻塞后续有效提交。
