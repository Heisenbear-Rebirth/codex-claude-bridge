# 自定义消息与维护提示词

在管理页右上角打开 **提示词设置**。设置作用于此管理台管理的所有项目，保存在安装目录的 `.cooperation/prompt-settings.json`；不会修改原生客户端的全局配置。

## 可编辑内容

| 分类 | 内容 |
| --- | --- |
| Codex 消息 | 进入模型上下文的前缀、后缀，默认均为空。 |
| Claude 消息 | 进入模型上下文的前缀、后缀，以及仅用于界面展示的标签。 |
| OpenCode 消息 | 进入模型上下文的前缀、后缀；默认保留原有协作来源说明。 |
| 交付文档 | 压缩前保存交接内容的提示词。 |
| 恢复上下文 | 压缩后读取交接内容的提示词。 |
| 继续任务 | 原本正在工作时，恢复结束后发送的继续提示；原本空闲时不发送。 |

消息前后缀和 Claude 显示标签可以留空。前后缀按原样使用，并与原消息用空行隔开；发送方信息、消息编号和正文会保留。Codex 原生的 `codex_delegation` 外层及各客户端的内部压缩摘要提示词由原生客户端管理。

## 编辑与预览

选择左侧分类后编辑内容。维护模板支持插入 `{{documentPath}}`、`{{cycleId}}`、`{{sessionId}}`、`{{client}}`；交付和恢复模板还必须各保留一个 `{{checkpoint}}`。它在实际发送时替换为本次流程的正确回执工具、阶段凭证和文档路径。凭证不由用户填写，也不会在设置预览中展示真实值。

预览可切换维护接收端；Claude 消息可分别预览模型接收内容和界面显示内容。预览只使用示例数据，不发送消息、不触发维护。

“恢复当前项默认”和“全部恢复默认”都只修改编辑草稿，点击 **保存设置** 后才生效。保存会检查配置版本；其他窗口已修改设置时，保留当前草稿并提示重新打开，避免覆盖对方的修改。

## 生效时间

- 普通消息在进入队列时保存当时的前后缀；后续修改不会改变已经排队或投递的消息。
- 维护流程在下一次发送交付、恢复或继续提示时读取新设置。显式重试也采用新内容；已发送提示不自动重发。
- Claude 显示标签在收到原生消息回显时读取设置，不改写模型接收的正文。
- 首次升级此功能后，已打开的 OpenCode 后端和 Claude wrapper 仍缓存旧代码；请在其原生任务结束后正常重开一次。之后修改设置无需重启。

189 项自动测试通过。新增测试覆盖保存与重启持久化、CSRF、并发版本冲突、模板变量校验、队列前后缀固定、OpenCode 热读取与重复消息识别、Claude 显示标签热读取，以及维护阶段实际使用自定义提示并保持两次回执约束。

隔离 Chrome 在桌面及 390px 手机视口验证编辑、预览、保存、刷新、清空提示、恢复默认、冲突处理和无横向溢出，页面错误为 0。隔离真实 OpenCode 1.18.30 后端配本地模拟模型完成自定义提示词的软/硬维护与后续消息投递；每轮一次压缩、两次原生回执，强阈值流程按条件发送自定义继续提示。
